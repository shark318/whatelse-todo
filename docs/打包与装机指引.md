# 「还有什么」打包与装机指引

> 从一台什么都没装的 Windows 电脑，到手机上能用的 App。
> 全程大约 **40~60 分钟**（其中大半是等云打包排队）。

---

## 0. 开始前须知

| 项目 | 说明 |
| --- | --- |
| **需要准备** | 一台 Windows 电脑、一台小米/红米手机、数据线（或微信/QQ） |
| **不需要** | Android Studio、JDK、Android SDK、应用商店开发者账号、服务器、域名 |
| **会花钱吗** | 不会。HBuilderX 免费，DCloud 账号免费，云打包有免费额度 |
| **唯一的外部账号** | DCloud 账号（云打包必需） |

**建议的操作顺序**：第 1 步 → 第 2 步 → **先在 HBuilderX 里跑一次「新建空项目 + 云打包」把链路验证通**（对应开发文档 M0 里程碑）→ 再开始写业务代码。

## 0.5 先搞清楚：代码是怎么变成手机上的 App 的

**有两套完全不同的流程，别搞混。**

### 路径 A · 开发调试：边写边看，**根本不用打包**

| 步骤 | 操作 |
| --- | --- |
| 1 | 手机用数据线连电脑；手机上打开「设置 → 关于手机 → 连点 MIUI 版本 7 次」开启开发者模式，再到「更多设置 → 开发者选项」里打开 **USB 调试** |
| 2 | HBuilderX 菜单：**运行 → 运行到手机或模拟器 → 选择你的设备** |
| 3 | 手机上会自动装一个叫 **HBuilder** 的调试基座 App，你的程序立刻在里面跑起来 |
| 4 | 改完代码按 `Ctrl+S` 保存，**手机上瞬间刷新**——不打包、不重装、不用等 |

> 特点：**秒级反馈**。缺点是手机上运行的是"HBuilder"这个壳，不是你的独立 App，也不能长期日常使用。

### 路径 B · 正式使用：打包成独立的 APK

| 步骤 | 操作 | 大概耗时 |
| --- | --- | --- |
| 1 | HBuilderX：**发行 → 原生 App-云打包** | 点几下，1 分钟 |
| 2 | 等云端排队 + 编译 | 5~30 分钟 |
| 3 | 下载 APK，传到手机（数据线 / 微信） | 1 分钟 |
| 4 | 手机上点 APK 安装（允许"未知来源"） | 1 分钟 |
| 5 | 首次启动给通知权限 + 做 HyperOS 三项设置 | 2 分钟 |

> 装完之后，它就是一个**独立 App**，不再需要 HBuilder，也不需要电脑。

### 两条路径的关系

```
写代码 → 【路径 A】在手机上实时预览、调试 → 功能都对了
                    ↓
           【路径 B】打一个正式包 → 装到手机上日常使用
                    ↓
        以后再改代码 → 版本号 +1 → 重新走一遍 B → 覆盖安装（数据保留）
```

**A 用来改，B 用来用。** 不要每改一行代码就去云打包——那是拿菜刀削铅笔。

### 如果代码是别人（或 AI）生成的，怎么放进 HBuilderX 项目

| 拿到的文件 | 放到哪里 |
| --- | --- |
| `pages/xxx/xxx.vue` | 项目的 `pages/` 下，**保持相对路径完全一致** |
| `components/Xxx.vue` | 项目的 `components/`（没有就新建） |
| `common/xxx.js` | 项目的 `common/`（没有就新建） |
| `App.vue`、`main.js`、`pages.json`、`manifest.json` | 直接**覆盖**项目根目录的同名文件 |
| `static/xxx.png` | 项目的 `static/` |

放完后，在 HBuilderX 里对着项目右键 → 「重新识别项目」，或者干脆重启 HBuilderX，再按路径 A 运行一次看效果。

## 1. 注册 DCloud 账号

1. 浏览器打开 <https://dev.dcloud.net.cn/>
2. 点「注册」，用手机号或邮箱注册
3. 登录后进入「账号中心」，**完成实名认证**
   - 云打包需要实名；如果后面要做 UniPush 实测，没有实名会卡住
   - 认证方式：手机号 + 身份证，或人脸识别，几分钟就能过
4. 记下账号和密码

> ⚠️ 这一步不要跳过。没有实名认证的账号，云打包会在提交时被拒绝。

---

## 2. 安装 HBuilderX

1. 打开 <https://www.dcloud.io/hbuilderx.html>
2. 下载 **正式版 → App 开发版**
   - ⚠️ **一定要选「App 开发版」**。标准版没有 App 打包能力，选错了后面找不到「云打包」菜单
3. 解压到一个**纯英文路径**下，例如 `D:\HBuilderX`
   - ⚠️ 不要放在中文路径或 `C:\Program Files` 下，会导致插件加载失败
4. 双击 `HBuilderX.exe` 启动
5. 首次启动会提示下载插件，等它下载完成（可能需要几分钟）
6. **登录**：左上角头像 → 登录 → 用第 1 步注册的 DCloud 账号登录

---

## 3. 打开已建好的项目

**本项目已经写好放在 `D:\软件开发\whatelse-todo`，不需要新建。**

1. 菜单：**文件 → 打开目录**
2. 选中 `D:\软件开发\whatelse-todo`（含 `manifest.json`、`pages.json`、`pages/` 的那一层）
3. 打开后，左侧项目树里应能看到 `pages/`、`components/`、`common/`、`static/`、`App.vue`、`manifest.json`、`pages.json`

> ⚠️ **只「打开目录」，不要再「新建项目」**——新建会生成另一套空文件，跟你已有的代码打架。

### 3.1 重新获取 appid（必做，否则云打包必失败）

本项目的 `manifest.json` 里 `appid` 目前是占位值 **`__UNI__WHATELSE`**，云打包会拒绝这种占位 appid。

1. 左上角头像 → **登录 DCloud 账号**
2. 双击 `manifest.json` → 切到 **「基础配置」** 页 → 找到 **AppID** 一栏 → 点 **「重新获取」**
3. HBuilderX 会向 DCloud 申请一个真实的 `__UNI__xxxxxxx` 并写回该文件

> 拿到真实 appid 后**不要再手改**，它与 DCloud 后台的应用记录绑定。

## 4. 配置 manifest.json

在左侧项目树里双击 `manifest.json`，先看**「基础配置」**这个可视化页面：

| 字段 | 填什么 |
| --- | --- |
| 应用名称 | `还有什么` |
| 应用版本名称 | `1.0.0` |
| 应用版本号 | `100` |
| 应用描述 | `一个只问你「还有什么要做」的本地待办清单` |

### 4.1 精简 Android 权限（重要）

然后点顶部**「源码视图」**，找到 `"app-plus"` → `"distribute"` → `"android"` 这一段。

⚠️ **模板默认会塞进一大堆权限**（相机、通讯录、定位、录音、打电话……），这些本项目一个都不需要。把 `"permissions"` 数组整个替换成下面三个：

```json
"android": {
    "packagename": "com.whatelse.todo",
    "minSdkVersion": 21,
    "abiFilters": [ "arm64-v8a" ],
    "permissions": [
        "<uses-permission android:name=\"android.permission.VIBRATE\"/>",
        "<uses-permission android:name=\"android.permission.WAKE_LOCK\"/>",
        "<uses-permission android:name=\"android.permission.POST_NOTIFICATIONS\"/>"
    ]
}
```

| 权限 | 为什么需要 |
| --- | --- |
| `VIBRATE` | 提醒时可以震动 |
| `WAKE_LOCK` | 保证通知能准时弹出 |
| `POST_NOTIFICATIONS` | Android 13+ 发通知的运行时权限 |

`abiFilters` 只保留 `arm64-v8a` 可以让 APK 体积减半（近几年的小米机型都是 64 位）。

### 4.2 设置图标

1. `manifest.json` → **「App图标配置」**
2. 选一张 **192×192 的 PNG** 图片（图标设计方案见开发文档 9.2 的 Q3）
3. 点「**自动生成所有图标并替换**」

### 4.3 关于 appid

`manifest.json` 里的 `"appid"` 字段：

- 新建项目时可能是 `__UNI__XXXXXXX` 的占位形式
- **不要手改它**。第一次云打包时 DCloud 会自动分配一个真实的 appid 并写回这个文件
- 手改会导致打包失败

## 5. 云打包，生成 APK

### 5.1 先做 UniPush 实测（强烈建议）

在正式打包前，先花 10 分钟按**《开发文档》7.4 节**做一个最小验证，判断本地通知是否需要开通 UniPush。

这一步决定 `manifest.json` 里要不要勾选「Push(消息推送)」模块，**先验证比后补要省事得多**。

### 5.2 打包步骤

1. 菜单：**发行 → 原生 App-云打包**
2. 在弹出的打包对话框里逐项设置：

   | 选项 | 选什么 | 说明 |
   | --- | --- | --- |
   | 平台 | 勾选 **Android(apk包)** | 取消勾选 iOS（打 iOS 需要苹果证书，本项目不做） |
   | Android 包名 | `com.whatelse.todo` | 应与 manifest.json 里的 `packagename` 一致 |
   | 证书 | **使用公共测试证书** | 自己用够了；正式上架才需要自有证书 |
   | 打包方式 | 快速安心打包 | 若失败可改选「传统方式」重试 |
   | 广告联盟 | **不勾选** | 本项目无广告 |
   | 打包类型 | 正式版 | |

3. 点「**打包**」
4. 等待：免费版会排队，通常 **5~30 分钟**。控制台会显示进度
5. 打包完成后：
   - HBuilderX 控制台会给出 APK 的下载链接
   - 也可以去 <https://dev.dcloud.net.cn/> → 「我的应用」→ 找到对应应用 → 「打包记录」里下载
   - APK 同时也会落在本地项目的 `unpackage/release/apk/` 目录下

---

## 6. 把 APK 传到手机

三种方式，任选一种：

| 方式 | 步骤 | 推荐度 |
| --- | --- | --- |
| **数据线** | 手机连电脑 → 手机上选「传输文件」→ 把 APK 复制到手机的 `Download` 目录 | ⭐ 最稳 |
| **微信 / QQ** | 电脑上把 APK 发到「文件传输助手」→ 手机上点开下载 | ⭐ 方便 |
| **网盘** | 上传到自己网盘，手机上下载 | 可用 |

⚠️ 从微信/QQ 里直接点开 APK 安装，可能被拦截提示「无法打开」。遇到这种情况，**改用手机的「文件管理」App 找到下载的 APK 再点击安装**。

---

## 7. 在小米手机上安装

1. 打开手机的**「文件管理」**，找到刚传过去的 APK
2. 点击它，HyperOS 会弹出提示：
   > **「为了安全，你的手机不允许安装来自此来源的应用」**
3. 点提示里的「**设置**」→ 打开「**允许来自此来源的应用**」开关
4. 返回后继续安装
5. 可能还会弹出「**安全检测**」或「**应用未经安全检测**」的提示 → 选「**继续安装**」
   （不要点「取消安装」或「删除安装包」）
6. 安装完成，桌面出现「**还有什么**」图标

### 装不上时怎么办

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 「解析包错误」 | APK 下载不完整 | 重新下载/重新传输 |
| 「应用未安装」 | 已存在同包名的旧版本，或存储空间不足 | 先卸载旧版本（**注意会丢数据**），或清理空间 |
| 「签名不一致」 | 之前用别的证书装过同包名的 App | 卸载旧版本再装 |
| 找不到「允许来自此来源的应用」 | HyperOS 版本菜单不同 | 设置里搜索「未知来源」或「安装未知应用」 |

## 8. 首次启动的权限设置

**第一次打开 App 时，系统会弹窗：「要允许『还有什么』发送通知吗？」**

👉 **一定要点「允许」**。点了「不允许」，任务到点就不会有提醒。

### 如果误点了「不允许」怎么补救

1. 设置 → **通知管理**（不同版本可能叫「通知与控制中心」）
2. 找到「**还有什么**」
3. 打开「**允许通知**」开关

> 开发文档 F7.2 要求在设置页放一条常驻提示「通知权限未开启，点此去开启」，就是为这种情况准备的。

---

## 9. 让提醒准时：HyperOS 必做设置

Android 会主动限制后台 App 以省电，这会让提醒**不准时甚至完全不弹**。以下三项**必做**：

| 序号 | 设置项 | 路径 | 作用 |
| --- | --- | --- | --- |
| **1** | 通知权限 | 首次启动点「允许」；或 设置 → 通知管理 → 「还有什么」→ 允许通知 | 没开就完全不弹通知 |
| **2** | 自启动 | 设置 → 应用设置 → 应用管理 → 「还有什么」→ **自启动** → 打开 | 让 App 能在后台存活 |
| **3** | 省电策略 | 同一页面 → **省电策略** → 选「**无限制**」 | 防止系统在息屏后清理掉 App |

**可选但推荐的三项**：

| 序号 | 设置项 | 路径 |
| --- | --- | --- |
| 4 | 后台弹出界面 | 同一页面 → 权限管理 → 后台弹出界面 → 允许 |
| 5 | 锁定后台 | 打开最近任务 → 下拉「还有什么」卡片 → 点锁形图标 |
| 6 | 安装未知应用 | 在第 7 步安装时已经设置过 |

> 各 HyperOS 版本的菜单名称可能略有差异。找不到时，在**设置的搜索框**里搜「还有什么」，可以直接跳到该应用的所有设置项。

### 验收：确认提醒真的能用

1. 在 App 里新建一条任务，设置**2 分钟后**的提醒
2. 把 App 切到后台（按 Home 键），或直接息屏
3. 等 2 分钟 → **通知栏应该弹出「还有什么 / 买牛奶」**
4. 进阶验证补发：设一个 2 分钟后的提醒 → **下拉杀掉 App** → 等过点 → **重新打开 App** → 应该立即收到补发通知

## 10. 常见报错与排查

| 现象 | 最可能的原因 | 解决 |
| --- | --- | --- |
| 打包失败，提示需开通 UniPush | 本地通知依赖推送模块 | 去 <https://dev.dcloud.net.cn/> 完成实名 → 开通 UniPush（**免费**）→ manifest 勾选「Push(消息推送)」→ 重新打包 |
| 云打包一直排队 | 免费版排队机制 | 耐心等；避开工作日晚间高峰 |
| HBuilderX 里找不到「云打包」菜单 | 装成了标准版 | 重新下载「**App 开发版**」 |
| 打包报「appid 不合法」 | 手改过 appid | 把 appid 改回 `__UNI__XXXXXXX` 占位形式，让云打包自动分配 |
| 装到手机后打开闪退 | `abiFilters` 与手机不匹配 | 删掉 `abiFilters` 配置，重新打包一次对比 |
| 通知完全不弹 | 通知权限没给 | 设置 → 通知管理 → 「还有什么」→ 允许通知 |
| 通知时有时无 / 不准时 | 省电策略在限制 | 第 9 步的三项必做设置重新检查一遍 |
| 提示更新装不上 | `versionCode` 没递增 | 见第 11 步 |

---

## 11. 以后更新版本怎么做

1. 打开 `manifest.json` → 基础配置：
   - **应用版本号**（versionCode）**+1**，例如 `100` → `101`
   - **应用版本名称**（versionName）改成 `1.0.1`
2. 重新云打包（第 5 步）
3. 把新 APK 传到手机，**直接安装，不要先卸载旧版**
   - 同一个包名 + 同一个证书 = 覆盖安装，**数据会保留**
   - 一旦卸载，本地数据全部丢失，且没有备份手段（见开发文档 9.2 的 Q1）

> ⚠️ **务必继续使用同一个证书**（继续用公共测试证书即可）。换了证书，覆盖安装会失败，只能卸载重装 —— 而那就意味着数据全丢。

## 附录 A：能不能用 GitHub 上的开源项目来打包 APK？

**能，但对这个项目不值得。** 先把原理说清楚：

> **uni-app 打包 APK，绕不开 DCloud 的 Android 运行时 SDK。**
> 无论走哪条路，最终都是同一个公式：
> **你的 Vue 代码 → 打成一个 www 资源包 → 塞进 DCloud 的 Android SDK 工程 → 用 Gradle 编译成 APK**

所以 GitHub 上那些项目**不是"DCloud 打包器的替代品"，而是"把 DCloud 的离线打包流程自动化 / 容器化"的工具**。

### 三条路对比

| 方案 | 代表作 | 需要准备什么 | 适合谁 |
| --- | --- | --- | --- |
| **A. HBuilderX 云打包**（本项目采用） | — | 一个 DCloud 账号，点两下菜单 | 一年打几次包的个人项目 ✅ |
| **B. 本地离线打包** | `dcloudio/HBuilder-Integrate-AS`（DCloud 官方工程，社区有多个 fork） | Android Studio（约 10 GB）+ JDK + Android SDK + 自己管理签名文件 | 需要加原生代码、或完全不能联网 |
| **C. Docker / GitHub Actions 自动打包** | `luckymiaow/uni-builder`（「uniapp docker 离线打包工具」，13★）、`guodongAndroid/uniappx-offline-for-android-template`（25★） | **先把 B 跑通**，再把离线 SDK 塞进仓库、把签名密码配成 secrets | 团队协作、需要 CI/CD |

### 不用它们的三个理由

1. **要先会走路才能跑** —— C 方案的前提是 B 已经跑通。而 B 的工作量（装 Android Studio、配 SDK/NDK、处理 Gradle 与离线 SDK 的版本兼容）**比你写这个 App 本身还大**。
2. **那些项目星数低、维护弱、版本耦合强** —— 检索到的最多 25 星，且依赖的离线 SDK 版本一旦升级就可能全崩，出问题几乎没人能帮你。
3. **你的打包频率不需要自动化** —— 一年打几次包，云打包排队 10 分钟完全能接受；而自动化方案要你先付出 1~2 天的搭建成本。

### 什么时候该换成 B 或 C

出现下面任一情况时再考虑：

- **需要加原生代码** —— 比如把提醒升级成 AlarmManager 级的定时通知（见开发文档 7.6 方案 B）
- **每周要打很多次包** —— 云打包的排队时间变成瓶颈
- **要多人协作、构建可复现** —— 需要 CI 保证每次产出的包一致

到那时你已经有能力驾驭它了。**现在用方案 A。**
